# 需求说明文档

> 本文档是 binwh.quant-pilot 量化投研平台的需求基线。数据库设计、接口设计、详细设计与部署文档均须可追溯至本文档的需求条目（FR-xxx / NFR-xxx）。
> 条目状态约定：未特别标注者为"已实现"（以代码现状为准）；标注"（待实现）"者为已明确的需求缺口，按现状逆向整理后作为正式需求收录。

## 1. 概述

### 1.1 项目定位

binwh.quant-pilot 是一个面向个人投资者的轻量级量化投研平台（pilot 形态）：以 A 股/港股核心指数与 ETF 日线行情为数据基础，提供行情数据自动同步、技术指标计算、基于机器学习的市场状态（regime）识别，以及可视化研究看板，形成"数据 → 指标 → 状态识别 → 可视化"的一站式研究闭环。

### 1.2 目标用户

- 个人投资者：关注核心宽基/行业 ETF 配置，需要直观查看行情、指标与当前市场状态。
- 量化研究者：需要可复现的状态识别管线（固定随机种子）、可追溯的训练运行记录与逐日状态序列。

系统为单用户自部署场景，无多租户（见 5.2 非目标）。

### 1.3 核心价值

1. 数据自动化：每日定时增量同步标的池行情，免人工维护数据。
2. 多源容错：akshare 为主、baostock / 国信接口为备的多级数据源回退与熔断，降低免费数据源不稳定的影响。
3. 研究可复现：市场状态识别管线参数化且固定随机种子，训练运行与逐日状态全部落库可追溯。
4. 轻量部署：docker compose 一键启动前后端容器，数据库使用远程托管 MySQL，单机即可运行。

## 2. 系统总体描述

### 2.2 系统边界（非目标）

以下为明确的非目标，不属于本期需求：

- 多租户 / SaaS 化、用户角色权限分级（单一"注册用户"角色）。
- 实盘交易、下单、组合管理。
- 分钟级 / tick 级数据、Level-2 行情（仅日线 K 线）。
- 通用策略回测框架（市场状态识别仅做状态判定，不做策略绩效归因）。
- 移动端原生应用。

### 2.3 用户角色

| 角色 | 描述 | 权限 |
| --- | --- | --- |
| 注册用户（个人投资者/研究者） | 自行注册账户并登录的唯一用户角色 | 查看全部行情/指标/状态数据、触发数据导入与模型训练、管理自身会话 |

无管理员等更高角色；系统不提供用户间数据隔离需求（单用户场景）。

## 3. 功能需求

优先级定义：高——基线功能，缺失则系统不可用或核心价值不成立；中——重要增强，缺失显著降低可用性；低——改进项。

### 3.1 用户认证（FR-AUTH）

- FR-AUTH-001. 系统支持用户注册：提交用户名与密码创建账户，成功返回 201，用户名重复返回 400。（优先级：高）
- FR-AUTH-002. 系统支持用户登录：验证凭通过后通过 httpOnly Set-Cookie 下发 access_token（有效期 15 分钟）与 refresh_token（有效期 7 天）。（优先级：高）
- FR-AUTH-003. 系统使用 bcrypt 对密码做不可逆加盐哈希后存储。（优先级：高）
- FR-AUTH-004. 系统提供 token 刷新端点：持有有效 refresh_token 的客户端可换取新的 access_token。（优先级：高）
- FR-AUTH-005. 系统提供登出端点：清除认证 Cookie，终止当前会话。（优先级：中）
- FR-AUTH-006. 系统提供当前用户信息查询端点：仅对已认证请求返回用户资料，未认证请求返回 401。（优先级：中）
- FR-AUTH-007. 行情数据、技术指标、市场状态三类业务路由必须要求登录访问，未认证请求统一返回 401。（优先级：高，待实现）
- FR-AUTH-008. 认证 Cookie 的 secure 属性必须可配置，以同时支持 http 单机部署与后续 https 升级。（优先级：中，待实现）
- FR-AUTH-009. 前端对受保护路由做组件级守卫：未登录用户访问受保护页面时渲染 403 提示而非业务内容。（优先级：中）
- FR-AUTH-010. 前端 HTTP 客户端在收到 401 时自动以 refresh_token 刷新 access_token 并重放原请求，同一时刻仅允许一次刷新（单飞），刷新失败则引导至登录页。（优先级：中）

### 3.2 行情数据（FR-DATA）

- FR-DATA-001. 系统支持从 akshare 获取 A 股 ETF/指数/股票/基金四类标的的日线 K 线（OHLCV）数据。（优先级：高）
- FR-DATA-002. akshare 数据源内部支持多级回退：腾讯源失败后自动切换新浪源。（优先级：高）
- FR-DATA-003. 系统支持 baostock 作为 A 股日线稳定备用数据源。（优先级：中）
- FR-DATA-004. 系统支持国信（guosen）接口作为指数/ETF 备用数据源，并带熔断保护：连续失败达阈值（默认 5 次）后冷却（默认 300 秒）。（优先级：中）
- FR-DATA-005. 系统维护预定义标的池：核心宽基 ETF、行业/主题 ETF，以及核心指数（含上证综指、沪深300、中证500、上证50、恒生指数、国债收益率与汇率代理等）。（优先级：高）
- FR-DATA-006. 系统支持按沪深300成分股构建个股标的池，并按总市值降序排列。（优先级：中）
- FR-DATA-007. 系统支持批量导入标的日线数据：单标的失败记录至 import_errors 表，并支持按失败记录重试。（优先级：高）
- FR-DATA-008. 批量导入必须限速与限并发（默认相邻请求间隔 2 秒、并发 2），避免触发数据源封禁。（优先级：高）
- FR-DATA-009. K 线入库采用 upsert（ON DUPLICATE KEY UPDATE）语义：同一标的同一交易日重复导入不产生重复行，已有行被最新值覆盖。（优先级：高）
- FR-DATA-010. 系统内置每日同步调度器：上海时间每个交易日 15:05 自动增量同步标的池行情，跳过周末，单次失败后 30 分钟重试。（优先级：高）
- FR-DATA-011. 系统提供按标的与日期区间查询日线 K 线的 API，覆盖股票/指数/ETF 三类。（优先级：高）
- FR-DATA-012. 系统提供 ETF 列表查询 API，返回代码、名称、跟踪指数、最新价与涨跌幅。（优先级：中）
- FR-DATA-013. 系统提供手动触发单标的同步的 API。（优先级：中）
- FR-DATA-014. 系统提供导入进度查询 API，展示批量导入的完成与失败情况。（优先级：中）

### 3.3 技术指标（FR-IND）

- FR-IND-001. 系统支持计算 MACD 指标（DIF/DEA/HIST）并持久化。（优先级：高）
- FR-IND-002. 系统支持计算 RSI 指标并持久化。（优先级：高）
- FR-IND-003. 系统支持计算 Bollinger 通道（上/中/下轨）并持久化。（优先级：高）
- FR-IND-004. 系统支持计算 Keltner 通道（上/中/下轨）并持久化。（优先级：中）
- FR-IND-005. 系统支持计算 ATR 指标并持久化。（优先级：中）
- FR-IND-006. 指标计算支持前复权/后复权（adjust_mode）选择，无复权因子时按不复权处理。（优先级：中）
- FR-IND-007. 行情导入完成后系统自动对该标的已有全量 K 线重算指标，并整体更新 indicator_values 存储。（优先级：高）
- FR-IND-008. 系统提供按标的查询已算指标的 API（单指标与全指标两种粒度）。（优先级：高）

### 3.4 市场状态识别（FR-REGIME）

- FR-REGIME-001. 系统支持基于日级行情特征（多周期收益率、实现波动率等）训练市场状态识别模型，按市场（A 股/港股）独立建模。（优先级：高）
- FR-REGIME-002. 识别管线按"特征工程 → PCA 降维（保留累计方差 0.95）→ HMM（hmmlearn，默认 3 状态）→ LogisticRegression 状态预测"顺序执行。（优先级：高）
- FR-REGIME-003. 管线超参数可配置：HMM 状态数（默认 3）、PCA 方差比例（默认 0.95）、波动率 span（默认 21）、收益率窗口（默认 5/21/63）、随机种子（默认 42，保证可复现）。（优先级：中）
- FR-REGIME-004. 每次训练生成一条运行记录（regime_runs），逐日状态结果持久化至 regime_states，二者关联可追溯。（优先级：高）
- FR-REGIME-005. 系统提供按市场查询逐日状态序列与训练运行历史的 API。（优先级：高）
- FR-REGIME-006. 系统提供手动触发训练的 API（单市场与全市场两种粒度）。（优先级：中）
- FR-REGIME-007. market_regime 模块必须支持可选加载：hmmlearn 不可用时训练接口不可用，但状态查询接口仍正常服务，后端进程不因该依赖缺失而启动失败。（优先级：中）

### 3.5 前端展示（FR-FE）

- FR-FE-001. 系统提供登录与注册页面，注册/登录失败时展示后端返回的错误信息。（优先级：高）
- FR-FE-002. Dashboard 支持选择标的查看日 K 线图（基于 Lightweight Charts v5），并按市场状态对背景着色（平静=绿、动荡=红）。（优先级：高）
- FR-FE-003. Dashboard 展示当前市场状态摘要卡片（状态、对应交易日等关键信息）。（优先级：中）
- FR-FE-004. ETF 页提供 ETF 列表（代码/名称/跟踪指数/最新价/涨跌幅），并支持展开单只 ETF 查看其 K 线图。（优先级：高）
- FR-FE-005. 指标页支持按标的查看技术指标图表（MACD/RSI/Bollinger 等）。（优先级：中）
- FR-FE-006. 前端路由采用 Hash 模式，保证静态资源部署与 nginx 反代场景下无需额外 history 回退配置。（优先级：低）

### 3.6 部署（FR-DEPLOY，目标态）

- FR-DEPLOY-001. 系统支持 docker compose 一键启动：backend 容器 + frontend/nginx 容器，数据库不入容器。（优先级：高，待实现）
- FR-DEPLOY-002. 数据库使用远程托管 MySQL（阿里云 RDS，库名 stockdb），应用通过连接串接入。（优先级：高）
- FR-DEPLOY-003. 所有机密（数据库口令、JWT secret、GS_API_KEY）必须经 .env 环境变量注入，代码与容器镜像中不得硬编码，部署文档仅以占位符示例。（优先级：高，待实现）
- FR-DEPLOY-004. 前端 nginx 容器将 /api/ 同源反向代理至 backend:8000，前后端同源、无跨域请求。（优先级：高）
- FR-DEPLOY-005. 目标部署形态为单机 http 部署，架构与配置预留升级 https 的能力（结合 FR-AUTH-008）。（优先级：中，待实现）
- FR-DEPLOY-006. JWT secret 必须在部署时注入生产随机值，禁止以代码内默认值运行生产服务。（优先级：高，待实现）

## 4. 非功能需求

### 4.1 安全（NFR-SEC）

- NFR-SEC-001. 认证凭据（access/refresh token）只能通过 httpOnly Cookie 传输，禁止写入 localStorage 等可被 XSS 读取的存储。（优先级：高）
- NFR-SEC-002. 密码仅以 bcrypt 加盐哈希形式存储，数据库泄露时不可还原明文。（优先级：高）
- NFR-SEC-003. 所有数据库访问必须经 ORM 参数化查询，禁止字符串拼接 SQL，防止 SQL 注入。（优先级：高）
- NFR-SEC-004. 机密信息（口令、API key、secret）不得进入代码仓库与运行日志；配置统一经 .env 注入。（优先级：高）
- NFR-SEC-005. token 生命周期可配置且默认短效：access_token 不超过 15 分钟，refresh_token 可经登出即时失效。（优先级：高）

### 4.2 性能（NFR-PERF）

- NFR-PERF-001. 单标的 K 线查询 API（约 1 年日线，≤250 根）响应时间 P95 < 1 秒。（优先级：高）
- NFR-PERF-002. 前端 K 线图可流畅渲染不少于 2000 根日 K，缩放/平移交互无可感知卡顿。（优先级：中）
- NFR-PERF-003. 标的池全量批量导入（约 40 个标的）在单次运行内完成，失败标的可经重试续传，无需全量重来。（优先级：中）
- NFR-PERF-004. 单标的指标全量重算（约 10 年日线，≈2500 根）在 10 秒内完成。（优先级：中）

### 4.3 可靠性（NFR-REL）

- NFR-REL-001. 任一数据源故障时系统自动回退至备用源，单源故障不中断整体导入流程。（优先级：高）
- NFR-REL-002. 备用源连续失败达阈值后熔断并冷却（默认 300 秒），冷却期结束后自动恢复尝试。（优先级：中）
- NFR-REL-003. 数据写入必须幂等：任意重复导入或调度重试不产生重复数据、不损坏既有数据（与 FR-DATA-009 对应）。（优先级：高）
- NFR-REL-004. 后端进程重启后调度器自动恢复运行，可选模块（hmmlearn）缺失时核心行情与查询功能不受影响、服务不崩溃。（优先级：高）

### 4.4 可维护性（NFR-MAINT）

- NFR-MAINT-001. 四件套文档（需求/数据库设计/接口设计/详细设计）与部署文档齐备，库表与接口设计条目可追溯至本文档需求 ID。（优先级：高）
- NFR-MAINT-002. 后端关键路径（注册/登录、导入幂等、指标计算）须有可自动化回归的测试用例；前端关键交互须有最低限度的手工验收清单。（优先级：高，待补全）
- NFR-MAINT-003. 全部配置集中管理（pydantic Settings + .env），新增配置项必须带默认值且不破坏既有部署。（优先级：中）
- NFR-MAINT-004. 前后端均使用强类型约束（TypeScript / pydantic schema + SQLAlchemy 模型），接口契约以 schema 定义为准。（优先级：中）

## 5. 约束与假设

### 5.1 技术栈约束

- 后端：Python + FastAPI + SQLAlchemy 2.x（async）+ MySQL（aiomysql 驱动），服务入口与生命周期管理在 FastAPI app（lifespan 内启动调度器）。
- 前端：Vue 3（`<script setup>`）+ TypeScript + Ant Design Vue 4 + Vue Router 4（Hash 模式）+ Axios + Lightweight Charts v5 + Vite 5；不引入全局状态库（如 Pinia）。
- 机器学习：scikit-learn + hmmlearn；hmmlearn 存在本机 C++ 编译失败的历史，因此其依赖必须保持可选（见 FR-REGIME-007）。

### 5.2 外部依赖与数据源限制

- akshare：主力免费数据源，接口易变动、有访问频率限制，须限速并做多级回退（FR-DATA-002/008）。
- baostock：免费稳定 A 股源，作为备用。
- 国信接口：限免服务，随时可能失效，需 API key（经 .env 注入），必须带熔断保护（FR-DATA-004）。
- 免费源不提供服务等级承诺：数据缺失或延迟属预期行为，系统只需保证"尽力同步 + 失败可重试"，不承诺数据完整性达标。

### 5.3 部署约束

- 单机 docker compose 部署；数据库为远程阿里云 RDS（不入容器），网络可达性由部署环境保证。
- 当前为 http 部署，https 为后续升级项。

### 5.4 假设

- 单用户使用：不并发多人使用，无租户隔离与权限分级需求。
- 交易日历以 A 股为准：调度器仅跳过周末，法定节假日由"数据源无数据则自然跳过"兜底，不单独维护节假日表。
- 用户具备基本的量化研究背景，能自行解读指标与市场状态含义，系统不提供投资建议。

## 6. 验收标准

| 编号 | 对应需求 | 验收判定 |
| --- | --- | --- |
| AC-01 | FR-AUTH-001/002/003 | 重复用户名注册返回 400；登录成功响应 Set-Cookie 含 httpOnly 的 access_token 与 refresh_token；users 表密码字段为 bcrypt 哈希格式（`$2b$` 前缀），无明文。 |
| AC-02 | FR-AUTH-007（待实现） | 未携带有效认证 Cookie 请求 /api/data、/api/indicators、/api/market_regime 任一端点，均返回 401；携带有效 Cookie 返回 200。 |
| AC-03 | FR-DATA-009 | 对同一标的同一交易日连续导入两次，K 线表行数不变，字段值等于最后一次导入值。 |
| AC-04 | FR-DATA-004 / NFR-REL-002 | 模拟备用源连续失败 5 次后，冷却期（300 秒）内的请求不再发起对该源的网络调用；冷却结束后恢复调用。 |
| AC-05 | FR-DATA-010 | 在交易日 15:05（上海时间）后检查，各标的仅新增晚于库内最新交易日的 K 线；周末不触发同步；人为制造失败后 30 分钟内观察到重试。 |

## 7. 术语表

| 术语 | 说明 |
| --- | --- |
| OHLCV | 开盘价/最高价/最低价/收盘价/成交量，日线 K 线的基本字段。 |
| K 线（Kline） | 按交易日聚合的价格序列，本系统统一为日级。 |
| ETF | 交易型开放式指数基金，本系统标的池的主要品种。 |
| 标的池（Universe） | 系统预定义的导入与同步范围：核心宽基 ETF、行业 ETF、核心指数、沪深300成分股。 |
| 复权（Adjust） | 对历史价格做前复权/后复权调整以消除分红除权跳变；adjust_mode 指定方式。 |
| MACD / RSI / Bollinger / Keltner / ATR | 本系统内置的五类技术指标（趋势/动量/通道/波动率）。 |
| 市场状态（Regime） | 由 ML 管线对市场所处环境的离散判定（如平静/动荡），按市场独立训练。 |
| PCA | 主成分分析，用于识别管线中的特征降维。 |
| HMM | 隐马尔可夫模型（hmmlearn 实现），用于状态序列建模。 |
| upsert | 存在则更新、不存在则插入的写入语义（MySQL ON DUPLICATE KEY UPDATE）。 |
| 熔断（Circuit Breaker） | 数据源连续失败达阈值后暂停调用一段时间（冷却）的保护机制。 |
| 单飞（Single-flight） | 并发 401 时仅放行一次 token 刷新，其余请求等待复用结果。 |
| JWT / httpOnly Cookie | JSON Web Token 令牌；httpOnly 指禁止 JS 读取的 Cookie 属性。 |
| bcrypt | 加盐慢哈希算法，用于密码存储。 |
| akshare / baostock | 两个免费 A 股数据源库；国信（guosen）为券商限免数据接口。 |
| 反向代理 | nginx 将前端同源的 /api/ 请求转发至后端服务的部署方式。 |
